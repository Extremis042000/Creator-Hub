# Google Services Setup

Every step here must be done by the founder, under the founder's own
Google account — none of it can be automated by an AI assistant (no
password, OTP, or session cookie should ever be requested for any of
these). Each section ends with the env var(s) it produces and where
they go.

## 1. Google OAuth (sign-in)

1. Go to [Google Cloud Console](https://console.cloud.google.com/) →
   create (or select) a project.
2. **APIs & Services → Credentials → Create Credentials → OAuth
   client ID.**
3. Application type: **Web application**.
4. **Authorized JavaScript origins:** add both
   `http://localhost:3000` (local dev) and the production frontend URL
   (`https://extremis-creator-hub.surya-chowdhury0412.workers.dev`).
5. Save. Copy the **Client ID** (the Client Secret is not used by this
   app — only the ID, since verification happens against Google's own
   JWKS, not a server-side OAuth code exchange).

**Produces:**
- Backend: `GOOGLE_CLIENT_ID` — same value on both local `.env` and Render.
- Frontend: `NEXT_PUBLIC_GOOGLE_CLIENT_ID` — **must match the backend
  value exactly**, in `.env.local` and as a Cloudflare build-time var.

## 2. Google Analytics (GA4)

1. Go to [Google Analytics](https://analytics.google.com/) → **Admin
   → Create Property.**
2. Add a **Web** data stream, URL = the production frontend URL.
3. Copy the **Measurement ID** (`G-XXXXXXXXXX`).

**Produces:** `NEXT_PUBLIC_GA_MEASUREMENT_ID` (frontend only, build-time).
Without this, the analytics code is fully inert — no script loads, no
events fire, nothing to remove later if you change your mind.

## 3. Google Search Console

1. Go to [Search Console](https://search.google.com/search-console/) →
   **Add property** → the production frontend URL.
2. Verify ownership — easiest method here is usually the HTML file
   upload or DNS TXT record option (whichever Search Console offers
   for a `*.workers.dev` subdomain).
3. Once verified, submit the sitemap: `{production URL}/sitemap.xml`
   (already generated by the app — no setup needed on this end beyond
   submitting the URL).

**Produces:** nothing that goes into this codebase — verification is
entirely on Google's side once ownership is confirmed.

## 4. Google AdSense

**Do not apply until there's real content and some traffic history**
— per the founder action checklist, applying prematurely can hurt
approval odds, and approval/timing is entirely Google's decision.

1. Once ready, apply at [Google AdSense](https://www.google.com/adsense/).
2. Once approved, find your **Publisher ID** (`ca-pub-xxxxxxxxxxxxxxxx`)
   in the AdSense dashboard.
3. Create ad units for the placements you want (tool pages, tools
   directory) and note each unit's slot ID.

**Produces:**
- Frontend: `NEXT_PUBLIC_ADSENSE_PUBLISHER_ID` (build-time).
- Update the placeholder `data-ad-slot` values in `AdSlot` usages
  (see `MONETIZATION.md` §5) with the real per-placement slot IDs.
- Also turn on the `display-ads` feature flag in `/admin` — both
  switches are required for ads to actually render (see
  `ARCHITECTURE.md`'s dual-switch pattern).

## After any of these

Whichever env var(s) you now have: set them in the relevant local
`.env`/`.env.local` for testing, then in Render's env var store
(backend vars) or as a Cloudflare build-time var (frontend
`NEXT_PUBLIC_*` vars — requires a rebuild+redeploy, see
`DEPLOYMENT.md`), and confirm the feature actually activates in
production before considering the step done.
