**Monetization phase ordering note:** phases 18-22 follow the founder-
approved sequence — Digital Products (19) before Affiliate (18 can run
in parallel since both are founder-controlled) before Display Ads (21)
before Premium/Subscription (22) — gated on real traffic validation
after phase 14-15 ship, not on a fixed calendar date.

**Explicit stop point:** per the founder's own instruction, implementation
(Phase 1 onward) does not begin until this blueprint set is approved.

**Deferred, not dropped — Neon Functions / Object Storage / Neon Auth:**
during Phase 5 setup, the Neon CLI's `skills`/`config` flow surfaced
Neon's separate serverless platform (edge Functions, S3-compatible
buckets, and a hosted "Neon Auth" service) as an available next step.
The founder decided to **hold this until last** and keep Spring Boot
as the single owner of business logic, auth, and data access for the
MVP, per the already-approved architecture (`02-technical-blueprint.md`).
Revisit only after the MVP tools are live and there's a concrete reason
(e.g. Neon Auth as a lighter-weight alternative to hand-rolled Spring
Security + Google OAuth, or Object Storage as an alternative to signed
Spring Boot download URLs for Phase 19's digital products) — not by
default just because the tooling offers it.
